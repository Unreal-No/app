# Art Pipeline — แผนเครื่องมือเสริมเพื่อเข้าใกล้ภาพอ้างอิง

เอกสารนี้เป็น**แผนสำหรับอนาคต** ตอนนี้ตัวสัตว์ทั้งหมดยังสร้างด้วยโค้ดใน `packages/creature`
(ดูสถานะและช่องว่างที่ [ART_DIRECTION.md](ART_DIRECTION.md)) เป้าหมายคือหาเครื่องมือที่ช่วยปิดช่องว่างกับ
[`reference/style-sheet.webp`](reference/style-sheet.webp) โดยไม่ทิ้งระบบยีนส์

## หลักการ: ยีนส์ไม่ผูกกับวิธีสร้างโมเดล

`packages/core` ส่งออกแค่ `Phenotype` (ชิ้นส่วน + ตัวเลข + สี) ส่วน `packages/creature` เป็นผู้ตีความ
ดังนั้นเปลี่ยนวิธีสร้างรูปทรงได้ทีละชิ้นโดยไม่แตะแกนเกม:

- allele ของ part-locus ระบุ "ผู้ให้ชิ้นส่วน" ได้ 2 แบบ — `procedural` (ปัจจุบัน) หรือ `glb:<ไฟล์>#<ชื่อ node>`
- ยีนส์ตัวเลข (ขนาดหู ความยาวหาง โครงร่าง ไขมัน) ขับ **morph target** ของ mesh แทนการสเกลทรงกลม
- สี/ลายแต้มยังใช้ระบบ "น้ำหนักสีตามตำแหน่งในท่าพัก" เดิม จึงใช้ได้กับ mesh ทุกแบบ
- ขน ตา ปาก สีหน้า ท่าทาง ใช้ของเดิมต่อได้

งานที่ต้องเพิ่มใน `packages/creature` เมื่อเริ่มใช้: ตัวโหลด GLB, ตารางจับคู่กระดูกกับ rig ปัจจุบัน และตัวผสม morph target

## ตัวเลือก (เรียงตามลำดับที่ควรลอง)

### 1. Blender แบบเขียนสคริปต์ (`bpy`) — "โรงอบโมเดล"

ใช้ Blender ผ่าน Python โดยไม่เปิดหน้าจอ สร้างชิ้นส่วนจากสคริปต์เหมือนเดิม แต่ได้เครื่องมือระดับโปรแกรมปั้น:

| ได้อะไร                                                            | ใช้ฟีเจอร์                                        |
| ----------------------------------------------------------------- | ---------------------------------------------- |
| หัว+ตัว+ขา หลอมเป็น mesh เดียวเนียนจริง (ตอนนี้เป็นทรงกลมซ้อนกันแล้วกลบรอยต่อ) | Voxel remesh + subdivision + smooth            |
| ข้อต่อโค้งงอสวยตอนขยับ                                                | Armature + automatic weights                   |
| เงาซอกมุมและทิศขนที่แม่นกว่า                                            | Bake AO / flow map ลง vertex color หรือ texture |
| รูปร่างแปรผันต่อเนื่อง (อ้วน-ผอม หูยาว-สั้น)                                | Shape keys → glTF morph targets                |

- **ข้อดี:** ยังเป็นโค้ดล้วน ไม่ต้องมีศิลปินหรือบัญชีบริการ ทำซ้ำได้ใน CI ผลลัพธ์เป็นไฟล์ GLB ที่ commit ได้
- **ข้อจำกัด:** ชุดผสมของ part-locus ต้องอบล่วงหน้าเป็นชิ้น (ไม่ได้สร้างสดตอนรัน) จึงต้องออกแบบจุดต่อชิ้นส่วนให้ดี
- **ผลการทดลองความเป็นไปได้:** ดูหัวข้อ "บันทึกการทดลอง" ท้ายเอกสาร

### 2. AI สร้างโมเดล 3D จากภาพ

ป้อนภาพอ้างอิง (หรือภาพชิ้นส่วนที่สร้างในสไตล์เดียวกัน) แล้วได้โมเดลตั้งต้น จากนั้นเก็บงานและตัดชิ้นส่วนด้วยสคริปต์ข้อ 1

| เครื่องมือ              | ลักษณะ             | หมายเหตุ                                       |
| -------------------- | ----------------- | --------------------------------------------- |
| Tripo                | บริการออนไลน์ + API | รีวิวปี 2026 หลายแห่งให้คะแนน topology/การผูกกระดูกดี |
| Meshy                | บริการออนไลน์ + API | ใช้งานทั่วไป มีแพ็กเกจฟรีจำกัด                       |
| Rodin (Hyper3D)      | บริการออนไลน์       | เด่นเรื่องตัวละคร ราคาสูงกว่า                       |
| Hunyuan3D, TRELLIS.2 | โอเพนซอร์ส รันเองได้ | ต้องมี GPU (เครื่องผู้ใช้หรือเช่า)                     |

- **ต้องใช้:** บัญชี/API key (กรอกผ่านฟอร์มข้อมูลลับของสภาพแวดล้อม ไม่พิมพ์ลงแชต) หรือเครื่องที่มี GPU
- **ความเสี่ยง:** สไตล์ไม่คงที่ข้ามชิ้น, โมเดลออกมาเป็นก้อนเดียวแยกชิ้นส่วนยาก, topology ไม่เหมาะกับการขยับ
- **สัญญาอนุญาต:** แพ็กเกจฟรีของหลายเจ้าห้ามใช้เชิงพาณิชย์หรือบังคับให้เครดิต — **ต้องอ่านเงื่อนไขปัจจุบันก่อนนำผลงานเข้า repo**
  (ตัวเลขราคา/เงื่อนไขที่พบตอนค้นคว้ามาจากบล็อกรีวิว ไม่ใช่เอกสารทางการ)

### 3. อบภาพล่วงหน้า (impostor baking)

ตอนสัตว์เกิดหรือโตขึ้น เรนเดอร์ตัวมันด้วยคุณภาพสูงครั้งเดียว (ขนหลายสิบชั้น + supersample) เก็บเป็นแผ่นภาพต่อท่า/มุม
แล้วตอนเล่นวาดแค่ภาพ

- **ข้อดี:** สวยขึ้นและเบาเครื่องลงพร้อมกัน (สำคัญกับแอปที่เปิดทั้งวัน) และยังเป็นโค้ดล้วน
- **ข้อจำกัด:** หมุนตัว/ผสมท่าได้ตามชุดที่อบไว้เท่านั้น ต้องออกแบบชุดท่าและการเปลี่ยนท่า

### 4. ทางเลือกสำรอง

- **Blender MCP บนเครื่องผู้ใช้:** ให้ Claude สั่ง Blender ที่เปิดอยู่บนเครื่องผู้ใช้ผ่าน Remote Control — เหมาะกับงานที่ต้องดูผลแล้วปรับด้วยตา
- **จ้างปั้นเฉพาะจุด:** เช่น หัวของตัวเอก แล้วใช้ระบบสี/ขน/สีหน้าเดิมครอบ
- **ภาพ 2D แยกชั้น:** ตรงภาพที่สุดแต่เสีย 3D จริง

## เกณฑ์ตัดสิน

| เกณฑ์                | คำถาม                                                        |
| ------------------- | ------------------------------------------------------------ |
| ความใกล้ภาพอ้างอิง     | เทียบด้วยหน้า Style Sheet (`apps/lab/stylesheet.html`) ช่องต่อช่อง |
| ระบบยีนส์             | ยังผสมข้ามสายพันธุ์ได้ทุกคู่และรูปร่างเปลี่ยนตามการเลี้ยงได้ไหม              |
| ค่าใช้จ่ายและสัญญาอนุญาต | ใช้เชิงพาณิชย์ได้ไหม ต้องจ่ายต่อเนื่องไหม                              |
| ขนาดและความลื่น       | ขนาดตัวติดตั้ง, เวลาโหลด, ภาระ GPU ตอนเปิดทิ้งไว้                    |
| ทำซ้ำได้              | สร้างใหม่ได้ด้วยสคริปต์ใน CI หรือต้องพึ่งมือคน                          |

## ลำดับที่เสนอ

1. พิสูจน์ข้อ 1 กับตัวเอกตัวเดียว: หลอมหัว+ตัวเป็น GLB แล้วเปิดใน Lab เทียบกับ procedural
2. ถ้าผ่าน: ทำตัวโหลด GLB + จุดต่อชิ้นส่วน แล้วย้ายทีละชิ้น (เริ่มจากหัวซึ่งมีผลต่อความน่ารักมากที่สุด)
3. ลองข้อ 3 กับแอป Desktop เพื่อดูผลต่อ GPU จริงบน Windows
4. ข้อ 2 ลองเมื่อผู้ใช้พร้อมเรื่องบัญชี/สัญญาอนุญาต
